# V0.5-C 回推滑行与最小反应延迟

本轮结束软件控制候选的扩展。滑行组使用 V0.5-B 控制器，延迟组固定为 `person_02 + balanced + narrow + symmetric`。两组均使用现有软件机械，控制步长为 20 ms。

## A 组　滑行与大角度回推

18 组自然回推覆盖 q=0.25、0.40 rad，三个回推幅值和三种原组合。q 表示推进量，机械回推速度为正。每组静止预处理 2 秒，回推 2 秒，松手再观察 2 秒。同一起点下两种 narrow 的预处理逐步相同。

从 q=0.40 rad 用 0.12 N·m 回推时，原自由区和小自由区对称模式在松手时仍分别为 q=0.3301 和 0.3477 rad。小自由区减阻已到 q=−0.0092 rad，机械速度为 0.8593 rad/s，松手后约 0.62 秒跨过对手侧 25° 线，约 0.96 秒到达反向限位。更弱的 0.065 N·m 输入在该起点下三组均未回到 q=0.05 rad。

在自由区设定完全相同的释放位置和速度后，两种 narrow 模式在六组试验中逐步一致。用 V0.5-B 的释放初态复算，松手 1 秒的模拟位置为 −0.31453 rad，黏性阻尼解析值为 −0.31485 rad，相差约 0.00032 rad。保留相同初态，把释放点移到阻力区，两模式会因仍有制动产生轨迹差异。自然回推试验中自由滑行的差异应结合实际释放位置、速度及限位分析。[A 组曲线、跨零速度、耗能与释放数据](test-results/2026-11-25-v05c-coast.md)

## B 组　延迟只作用于需求起点

首次在有效运行中检测到正阻力请求才计时。等待期间的有效请求为零，疲劳负载也按零请求更新。门打开时采用当前请求，从零开始按原 0.40 s 时间常数建立阻力。已有请求下降仍立即生效。需求归零、暂停、结束、故障、断联和超时都取消等待。时钟重复不推进，回退或超过 0.25 秒的跳变重新锚定。默认 0 ms 走旧计算，demo 在所有设置下走原基线。

固定遥测在全局 t=0.60 s 进入正需求。100 和 200 ms 的门分别在 0.70 和 0.80 s 打开，首次正下发为 0.72 和 0.82 s。多出的 20 ms 是从门开时建立锚点到下一个控制步。0 ms 沿用旧的零请求时间锚点，在 0.60 s 已有首个正下发。同施力闭环中，0.09 N·m 档只有 200 ms 跨过角线，0.12 N·m 档的 200 ms 则触模拟限位。[B 组时序、取消实验和九组闭环](test-results/2026-11-25-v05c-delay.md)

## 软件仿真复现

在 PC 仓库根目录两个 PowerShell 分别启动桥接和模拟器。TCP 接受整数 0–200 ms。比较时保持同一人物、方向模式和施力序列。

```powershell
.\.venv\Scripts\python.exe -m common.bridge --strategy balanced --resistance-profile narrow --return-mode symmetric --reaction-delay-ms 100 --log-file "$env:TEMP\arm-v05c-pc.jsonl"
.\.venv\Scripts\python.exe -m sim.mock_stm32 --torque 0.09 --sequence release:1.2,down:0.66,release:1.2,back:0.22,release:1.72
```

正式场景打开 `Assets/Scenes/ArmWrestlingMain.unity`，选择网络数据和乙（person_02）。串口入口 `real.run` 沿用原行为。A 组的匹配释放初态由离线脚本设置。两组复现命令、原始数据和绘图说明见各自报告。

## 验证

- Windows Python 共运行 107 项，106 通过，Linux PTY 1 项跳过。冻结 V0.5-B 的逐步对照覆盖所有四种有效曲线与方向组合、四个人物和三种策略，共 48,000 步。常规人物使用 0 ms，demo 设置 200 ms 检查旁路。原制动命令、诊断字段、UDP 回包逐步相等。TCP 接受合法延迟并拒绝非法值，串口入口拒绝实验参数。
- 正式 Unity 主场景使用 VR P3.0 `129c989` 搭配 narrow、symmetric、200 ms 和软件施力 0.18 N·m。实际 Editor Play 完成 5 局、35 个检查点，运行错误 0。用本地测试启动器记录 person_02 正需求、开门与首个正下发三个控制拍。按 Windows 单调时钟，实际开门约 219 ms，首个正下发约 250 ms。相较固定步长，在线循环按实际调度的控制拍采纳。退出 Editor 后 PC 记录超时和 STOP/0。[Editor 复验数据](test-results/2026-11-25-v05c-editor.json)

## 收口建议

- `legacy + symmetric + 0 ms` 继续作为默认及串口路径，作为历史对照。
- `narrow + symmetric + 0 ms` 是下一阶段优先的软件候选。方向减阻保留显式对照。100 ms 用于敏感性比较，200 ms 用于观察边界工况。
- 下一步转向实体 STM32 通信和无人台架的独立保护及标定。需要测量实际残余和静态抗转矩、零位和有效行程、惯量与阻尼、从指令到实测力矩的响应时间。人体手感和 PICO 尚待独立验证。
