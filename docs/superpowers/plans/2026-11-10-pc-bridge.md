# PC communication bridge V0.1 Implementation Plan

**Goal:** Three real local TCP processes exchange telemetry, brake commands and VR match state on Ubuntu using Windows-compatible standard-library Python.

**Architecture:** One PC event loop owns the latest validated STM32/VR state and runs at 50 Hz independently of VR updates. Separate TCP ports identify roles; UTF-8 JSON lines carry version and increasing sequence numbers. Missing/stale/faulted/paused inputs produce explicit stop commands. The simulated device also expires commands and opposes its current velocity locally.

**Tech Stack:** Python 3.10+ standard library; existing MuJoCo dependencies remain simulation-only.

**Spec:** User request in this chat; protocol and operation contract will be documented in `docs/pc-bridge.md`.

## Constraints and decisions

- Keep A/C/D geometry, existing control parameters, passive law, and `real/` unchanged.
- Move the pure control implementation to `common/control.py`; old imports re-export the same objects. Extract the existing speed regularization into a shared helper for device-side direction handling without changing its math.
- Default local ports: STM32 9101, VR 9102. One client per port; no authentication or physical safety claim.
- Telemetry timeout 0.25 s; VR timeout 1 s; command lifetime 200 ms. Use receiver monotonic time, not synchronized clocks.
- Connection errors invalidate that role; reconnect starts a new sequence. Malformed/nonfinite/out-of-range data cannot refresh freshness.
- Windows instructions use `py -3`, no POSIX-only IO/signals. Windows execution remains unverified on Ubuntu.
- Work inline on a dedicated branch in the existing clean home-directory checkout; user requested simple autonomous delivery to this repository.

## Review focus

Fragmented/coalesced TCP messages; NaN/bool/missing fields; duplicate sequences; silent/disconnected peers; stale commands during velocity reversal. Tests cover each at the relevant boundary. Slow or non-reading clients must not block the loop or create an unbounded output queue. Automatic resume on fresh valid data is simulation behavior, not a hardware safety policy.
