# STM32F405RGT6 ↔ PC 串口协议 V1.1（首次对接候选）

> 2026-11-27。第一次交付给下位机组的候选协议，线上 version=0x02。PC、模拟器和 C 参考已完成软件验证。实体固件、传感器物理量和本地授权规则待双方确认后冻结。文中的力矩字段用于离线编解码测试。

## 1. 分工与连接

PC 负责人物能力、策略、比赛状态及目标阻力；STM32 负责角度采集、机械零位、单位与方向换算、本地保护、已标定的目标力矩到执行输出映射。STM32 不需要 Unity、VR 协议或人物/疲劳算法。PC 提供独立 Tkinter 联调工具，可代替 VR 选人物、选策略及开始/暂停/结束。首次接板采用仅 STOP 的通信检查，励磁功率物理隔离、无人接触。

USB CDC 或 USART + 3.3 V USB 转串口均可使用相同字节流。USART 初始 115200、8N1；确认收发电平、接线和实际端口。建议遥测 100 Hz、命令 50 Hz，独立周期采样、通信与执行。USART 39 B 遥测耗时约 3.39 ms，22 B 命令约 1.91 ms，分别占全双工单方向带宽约 33.9%/9.5%。优先用已有中断/DMA 或非阻塞发送，不在采样中断/控制周期阻塞等待串口输出；暂不要求提高波特率。USB CDC 的 COM 波特率不等同 USB 总线速率。旧帧不做无限排队、重传过期控制目标或逐条同步等待 ACK。

## 2. 线上格式（固定长度、小端）

| 偏移 | 字段 | 字节 | 说明 |
|---:|---|---:|---|
| 0 | SYNC | 2 | A5 5A |
| 2 | version | 1 | 固定 02，不接受 01 作为 V1.1 |
| 3 | type | 1 | 01 TELEMETRY；02 BRAKE_COMMAND；03 SESSION_OPEN；04 SESSION_ACK |
| 4 | seq | 2 | uint16，小端 |
| 6 | length | 1 | payload 字节数 |
| 7 | payload | N | 按消息类型固定 |
| 7+N | crc16 | 2 | uint16，小端，覆盖 version 到 payload，不含 SYNC 与 CRC |

完整帧长 9+N；MAX_PAYLOAD=64，最大帧缓存 73 B。**64 是缓冲区上限，不表示任意长度合法。** V1.1 只接受 30/13/8/8 B 四种已定义 payload；未知版本、类型和长度拒绝并重新同步。CRC-16/CCITT-FALSE：poly=0x1021、init=0xFFFF、refin/refout=false、xorout=0，123456789→0x29B1。STM32F405 使用软件 CRC16；不直接采用其 CRC32 硬件。按字节移位/拷贝编解码，不把带填充的 C struct 直接当线上格式。支持任意分包/粘包/噪声、payload 内出现 A5 5A、错误头/CRC 后重新找帧，组帧超时初值 100 ms。

命令序号在会话内递增；遥测序号按会话内独立计数（未建会话的诊断流也可递增）；OPEN/ACK 帧头序号仅诊断，不与命令/遥测的有效序号基准混用。新序号判断 0<((new-last)&0xFFFF)<32768，65535→0 合法；会话建立时重置相应接收基准；重复旧帧不刷新控制数据或命令看门狗。

### 2.1 STM32 → PC：TELEMETRY，30 B

| payload 偏移 | 字段 | 类型 | 语义 |
|---:|---|---|---|
| 0 | angle_mrad | int32 | 主轴角，mrad；机械零位 0，用户向获胜侧压下为负 |
| 4 | velocity_mrad_s | int32 | 主轴角速度，mrad/s；方向与角度一致 |
| 8 | sensor_force_mn | int32 | 可选实测力，mN；未提供/未标定时填 0 且 FORCE_VALID=0 |
| 12 | status_flags | uint16 | 下表 |
| 14 | last_command_seq | uint16 | 本会话最近一次接受的命令线序号，ACK_VALID=1 才有意义 |
| 16 | applied_target_mnm | uint16 | 当前本地限幅后目标阻力幅值，mN·m；非实测力矩 |
| 18 | mcu_sample_ms | uint32 | 角度采样快照的 MCU 单调毫秒时间，非发送时间；HAL_GetTick 等 |
| 22 | session_id | uint64 | 当前会话，0 表示无有效会话 |

所有物理量以主轴侧为约定；sensor_force_mn 只表示测力通道实际力，不表示主轴力矩。mN/mrad/mN·m 是编码分辨率，不代表传感器精度。传感器若最终为直接扭矩传感器，第一步先令 FORCE_VALID=0，双方确认专用力矩字段/版本或单独实验日志后再传输，不在此字段中偷偷换单位；不影响首次角度/串口验证。

| bit | 名称 | 含义 |
|---:|---|---|
| 0 | READY | 设备初始化及基本运行条件满足 |
| 1 | FAULT | 设备故障 |
| 2 | ESTOP | 急停 |
| 3 | LIMIT | 行程越限 |
| 4 | ACK_VALID | 当前会话有已接受命令 |
| 5 | FORCE_VALID | 力测量有效（已标定、未过期） |
| 6 | ARM_READY | 本地运行授权有效，不等同正在制动 |
| 7 | ANGLE_VALID | 实际角度及机械零位有效，采集任务正常且未过期 |
| 8 | VEL_VALID | 实际角速度有效 |
| 9 | CMD_TIMEOUT | 命令看门狗超时，需检查通信恢复 |
| 10–15 | 保留 | 发送方置 0；接收方记录未知位并禁止 ENABLE |

速度/测力可暂不实现，字段填 0、有效位清零。PC 界面/日志标记无效，不当作真实零速/零力。当前真实串口对称阻力幅值仅需角度，允许速度无效情况下按明确的兼容内部占位运行；不得使用占位速度计算可称为实际功率/减阻的结果。角度无效一律禁止正常控制；原始角度可作为明确标记无效的诊断读数。READY、ARM_READY、ANGLE_VALID 是不同条件。无会话时 ACK_VALID=0、目标=0，仍周期发诊断遥测，便于首次接线查看。角度采集停滞时不得把旧角度附上新的采样时间假装新数据；MCU 在采集过期时清有效位。重复采样时间可以诊断更新状态，但不刷新角度采样有效时间；PC 对同会话 uint32 自然回绕做模差处理，异常倒退/停滞阻止正常控制。PC 到达时间与 MCU 采样时间分别记录，不相减冒充单程延迟。力/速度不同采样率时，各有效位反映通道自身有效性。

### 2.2 PC → STM32：BRAKE_COMMAND，13 B

| payload 偏移 | 字段 | 类型 | 语义 |
|---:|---|---|---|
| 0 | session_id | uint64 | 当前非零会话 |
| 8 | mode | uint8 | 0=STOP，1=ENABLE |
| 9 | target_torque_mnm | uint16 | 主轴侧无符号目标阻力幅值，mN·m |
| 11 | valid_for_ms | uint16 | 20..500 ms；PC 初始 200 ms，本地上限建议初始 200 ms |

保持原 V1 命令结构。STOP 必须携带 0。在匹配会话、帧合法、序号更新时，即使未授权/角度未标定/设备故障也接受 STOP 并更新 ACK，目标归零，不代表解除故障或获得授权。ENABLE 还要求本地独立保护、已确认会话、READY+ARM_READY+ANGLE_VALID、无 FAULT/ESTOP/LIMIT/未恢复的通信异常；MCU 依据台架标定与本地限制执行，未标定不允许带励磁正常对抗。不得通过通信指令绕过保护。字段可编码 65.535 N·m，不代表许可输出；设计额定主轴理想值约 48 N·m，真实能力、力矩变化限制、运行范围和人员测试允许值由机械/电气台架确认。

### 2.3 SESSION_OPEN / SESSION_ACK，均为 8 B

payload 只有 uint64 little-endian session_id，必须非零。PC 启动、新物理连接或会话失效后生成新非零随机编号。MCU 收到不同的合法 OPEN：先撤销旧命令及正常输出、清旧 ACK/命令序号，进入等待，然后保存编号并回 ACK；重复相同 OPEN 只再次应答，不恢复输出、不延长看门狗、不复位正常序号。MCU 复位后 session_id=0、未授权、无有效旧命令。会话编号不是加密身份认证。

## 3. 最小正常流程与异常规则

1. MCU 上电先保证本地禁止未经授权输出，开始周期遥测，未建会话填 0。PC 打开 COM，可显示合法遥测，但未收到匹配 ACK 且未见匹配会话遥测之前不允许 ENABLE；重试相同 OPEN（约 200 ms），首次等待可设 3–5 s 或在未握手时保持端口并明确提示，避免反复开关串口导致复位。
2. 握手完成后 PC 周期发送 STOP/0，MCU 返回当前会话及最近接受序号。PC 见该会话的 STOP ACK 后才允许进入比赛控制，并要求当前角度有效与本地许可。默认等待；选择人物、策略并人工开始才可能产生 ENABLE。
3. 正常周期命令与遥测独立运行。ACK 用于确认命令进度，不要求每次遥测都等于最新命令，不阻塞控制。PC 跟踪当前会话的实际完整写出序号与 ACK 进度；启动/切换给合理窗口，持续约 200 ms 有待确认命令而没有进度（或持续无法完整写出）时停止正常控制、提示、检查/重建会话。200 ms 是待验证初值，测实际延迟和误停率后调整。不能让重复旧 ACK 刷新确认进度。已写完串口 API 并非物理执行成功。
4. 收到无会话/不匹配会话遥测时先处理会话失效、再判断序号：旧控制遥测失效，停止正常输出，清旧状态并新握手；尚未握手阶段只显示诊断，不反复因相同未配对帧生成新编号。不得只用遥测 seq 推测复位。匹配会话的 ACK/遥测建立新基准，忽略迟到的旧会话控制数据。PC 恢复到等待/暂停，不能沿用故障前的 running 自动恢复非零目标。
5. PC 正常有效遥测超时初值 250 ms；VR 心跳初值 1 s；MCU 从接受合法新命令时开始独立计时，按 min(valid_for_ms,本地允许上限) 失效。错误 CRC、旧序号、错误会话及 OPEN/ACK 不续期。失效时 MCU 撤销命令、目标归零，设置 CMD_TIMEOUT，撤销当前会话/旧 ACK；新的合法会话和 STOP 可恢复通信诊断，通信超时位在新会话 STOP 被接受后清除，不能据此自动授权输出。真实执行失效动作由电气组结合突然卸力和机械风险确认；STOP 仅为零阻力请求，不保证摆臂立即停下。
6. 正常暂停、结束、等待持续 STOP，不必人工复位故障或重复物理授权。通信中断、复位、急停和故障之后，禁止自动恢复运行；非零输出需要新一轮显式人工开始/继续、当前本地许可和所有保护条件。当前实现以保守的本地授权规则为默认；若实际使用自锁使能开关，可协商仅在已确认 STOP/0 的空闲断开时保留本地硬件许可，仍须重新会话、确认 STOP 及明确开始；不得在没有实际电气方案时实现自动重新授权或要求额外采购按钮。真实急停/故障按本地硬件流程确认和复位，不能用 PC 命令自动解除。先验证无励磁、无人体的通信，再做独立保护确认后的无人台架。
