## P0：优先完成，作为交付条件

### 1. 原始通信诊断
现有 common/serial_protocol.py FrameParser 在找不到 SYNC 时丢弃杂散字节而未单独计数；real/stm32_link.py 已有 CRC/头/序号等计数，复用。
- 在现有唯一串口适配器统计 RX 累计字节、TX 实际被串口 API 接受的字节、解析出的合法帧数量、匹配会话和有效遥测数量；区分完整帧写出与 MCU ACK，不声称 API 写入成功等于设备收到。按连接明确统计口径；同 COM 内新会话保留累计值，断开重连重置。记录实际读取到的字节，而不是用 in_waiting 或理论频率估算。
- FrameParser 记录为同步而丢弃的字节数量；保留跨 chunk 尾部 A5 的行为，明确定义计数，避免 CRC/非法头/超时清理被误说成全部杂散字节。展示有限的最近 RX/TX Hex（例如各最后 32 或 64 字节，标为原始字节而非必然完整帧）；可以复制，不刷满主界面或日志。未收到、未实现、过期都正确显示。
- 主界面简单区分没有 RX、收到字节但无合法帧、已见合法诊断遥测但无匹配 ACK、已握手但尚未 STOP 确认、已确认但未获许可。故障提示列可能原因而非武断确诊。高频记录与界面刷新分离，保留原有解析、控制及队列边界。
- 测试无字节、ASCII 杂散文本、旧版本/坏头、坏 CRC、分包粘包及尾部 A5、正常帧恢复。实际虚拟 COM 验证 RX/TX 和计数提示；不打开真实带功率设备注入坏帧。

### 2. STOP 确认语义
real/stm32_link.py _accept_ack 目前仅根据 outstanding 中的 STOP 模式把 session_confirmed 设真，没有同时校验 applied_target_mnm。首次正常运行的门控要求当前会话合法新鲜遥测、已接受 STOP（ACK 真实对应当前会话完整写出的命令）且回报目标为 0。区分“STOP 已接受”“下位机目标已归零”和“可正常开始”。对于 ACK 对应 STOP 却回报非零的情况，在没有一致零目标证据前禁止开始，记录诊断并继续 STOP；不因为任意不同序号的瞬时差值误报，也不因等待而自动重试 ENABLE。后续正常运行时已有 ACK/故障/采样停滞/重连恢复和人工继续门控不减弱。测试先收到 STOP ACK+非零回报不能正常开始，后续收到匹配合法 STOP ACK+零回报才确认；仅 STOP 模式永远不发送 ENABLE。不要把目标为零称作实测制动力矩为零或机械停止。

### 3. C 解析器小范围防御性完善
现有 aw_parser_feed 逐字节消费，合法最大帧 39 B，小于 73 B 缓冲；尚未证实按约定使用或漏 drain 就能自然造成越界，不能在报告中称为已复现漏洞。仍为便携参考代码加显式写入前容量检查，异常满缓冲安全丢弃/重同步，保留诊断计数；防止 used 超出容量时再调用基于错误长度的 memmove。不要为此重做解析器或改 C 参考的正常 API/协议。增加边界、长噪声、连续异常帧、迟到/超时、漏 drain 等主机测试，能使用 ASan/UBSan 时加跑；明确哪些是故意构造边界而非原版真实复现。保持六条黄金帧和会话/看门狗回归。

### 4. 面板可读性与首次启动
- 基于现有 Tkinter/ttk 布局，状态位改紧凑分组/颜色+文字（READY、ARM_READY、ANGLE_VALID、VEL_VALID、FORCE_VALID、ACK_VALID 与 FAULT/ESTOP/LIMIT/CMD_TIMEOUT 的正反语义正确）；无数据/过期为未知，不用仅颜色判定。关键通信、授权、STOP 状态始终可见，详细报文可折叠或用页签，给事件列表留空间。在常见 Windows 1366x768/1920x1080 或可用屏幕缩放下验证不截断。
- 角度旁明确显示当前 legacy 原自由区 q<=0.25 rad、阻力区 q>0.25 rad（机械角低于约 -14.3°），阈值从实际生效配置读取而非额外另定义。无有效角度时不判区。比赛等待/暂停/未授权等状态优先于自由区解释；越过边界仍可因发力建立、疲劳或保护导致零目标，不宣称一定有实测阻力。
- 启动脚本检测实际使用的 Python 版本、tkinter、pyserial；缺失时提示中文安装/修复命令并保留窗口，不擅自安装。不增加必需依赖。

## P1：小而实用的交互与记录（同轮收口）
- 增加窗口置顶，可选，默认不强制。保留默认失焦暂停。若提供关闭失焦暂停的选项，仅在断开状态显式选择“仅软件/已物理隔离励磁的后台调试”并确认、持续显示醒目提示；这只是操作选项而非自动证明物理隔离或提供硬件授权。最小化/关闭窗口、主循环卡住、后端退出、遥测/ACK/许可异常、断联重连等原保护仍暂停或停止；不能靠后台线程维持陈旧 running，恢复必须人工继续。真实带功率运行使用默认保守配置，不允许此选项取消本地独立保护。仅 STOP 监测可以正常切到 IDE 而不运行比赛；焦点行为本身不是硬件安全机制。若实现有冲突，优先保留默认并交付置顶，不为该选项重构状态机。
- 可增加仅在面板获得焦点时有效的暂停快捷键（推荐 Ctrl+Space 或其他不干扰正常编辑的键），只暂停不自动恢复，不做系统级热键，不称“硬件急停”。醒目的暂停按钮始终保留。
- 使用 Tk Canvas 或已有轻量控件提供可折叠/页签的约 10 秒滚动趋势：角度与零位/原自由边界、PC 请求/完整写出目标与 MCU 回报目标。只用已有 5–10 Hz 本地快照，标明仅趋势显示，不拿低频图评价毫秒级响应；缺测断线，重新会话断开曲线/清缓存。力 N 与力矩 N·m 不同轴。固定有界缓存、避免重复加点和阻塞后端；不需要实时 100 Hz 绘图或新增绘图库依赖。重点是易排错，不为美术扩大工作。
- 简易离线日志分析入口（例如 tools/plot_experiment.py）：接受导出 ZIP 或 experiment.jsonl，无需连接设备。直接读 ZIP 中的日志而非随意解压外部路径；按会话和字段有效性解析，至少输出 CSV 与角度、完整写出目标、MCU 回报目标、有效测力、间隔/丢记录的统计。可用可选 matplotlib 绘图，未安装时给出明确提示或仍输出 CSV，不使它成为 GUI 启动依赖。以 command_written 的 target_mnm 为实际写出请求，不把它称作逐拍 PC 计算目标；pc.jsonl 中计算目标按实际低频口径标注。PC 单调时间和 MCU sample 时间分别处理，考虑 MCU uint32 回绕、会话切换、重复采样和 seq 跳变，不能相减当单向延迟；未提供的速度/力不补 0，不把目标回报当实测。使用已有 example-experiment.jsonl 与本次实际导出验证。若时间紧可先交 CSV 和简单离线图，不做复杂交互分析界面。
- 暂不打包 EXE、不新增第三套协议/自动扫描硬件、不调整真实力矩标定或改游戏美术。
