# STM32 上位机联调工具 V0.1

> 本页为历史说明。首次交接请使用 [V0.2 面板](stm32-debug-panel-v02.md)。

给下位机同学用的 Windows 面板。串口侧由 PC 原有的 `real.run` 完成握手、遥测解析和控制计算。当前串口使用 [V1.1](stm32-serial-v11.md)，线上版本 02。模拟比赛时，面板用同一个本地 UDP socket 收发 [VR V0.1](vr-udp-v01.md)，正式 VR 的 9102 端口留给 Unity。运行只需要 Python、Tkinter 和 pyserial。

## 启动

在仓库根目录打开 PowerShell。项目已有 `.venv` 时直接安装 pyserial 并启动。

```powershell
# 首次使用且没有 .venv 时执行这一行
python -m venv .venv

.\.venv\Scripts\python.exe -m pip install pyserial
.\start-stm32-debug.cmd
```

也可以双击 `start-stm32-debug.cmd`，或运行 `.\.venv\Scripts\python.exe -m tools.stm32_debug`。本次在 Python 3.11.5、Tk 8.6 和 pyserial 3.5 验证。若 Python 缺少 Tk，安装 Python 时勾选 Tcl/Tk。

使用虚拟串口时，先启动模拟 STM32。下面用 COM1↔COM2 举例，按自己电脑上的配对替换。程序持续模拟下压、回推和松手。

```powershell
.\.venv\Scripts\python.exe -m sim.mock_stm32_serial --port COM2
```

在面板点 **刷新**，选择另一端 COM1。串口默认 115200、8N1。只测握手和遥测时，模拟端无需 `--demo-arm`。要测比赛，关闭模拟进程，再在上条命令末尾加 `--demo-arm` 启动。该参数用于软件模拟器。

首次接实体板前，请下位机/电气组确认制动器励磁功率已物理隔离，设备旁无人接触。按 [实体联调流程](real-vr-stm32-integration-v01.md) 先验收握手和遥测。面板的暂停、结束和断开只会撤销 PC 的正常阻力请求。硬件急停、本地授权、限位与命令看门狗由下位机独立执行。

## 先查通信，再测比赛

1. 保持默认 **串口检查 · 仅 STOP**，点 **连接**。面板会主动尝试 V1.1 握手。匹配 SESSION_ACK 后，后端只发送 `STOP/0`。即使有程序向调试 UDP 端口发送 `running`，也不会使能制动。
2. 在左栏依次确认 **串口已打开 → SESSION_ACK 匹配 → 当前会话 STOP 已确认 → 角度有效 → 本地使能**。前三项正常但 `ARM_READY=0`，仍可验收串口通信。角度可独立标定，速度和测力可以暂未提供。只出现“串口已打开”时，先检查设备侧是否是配对的另一端、波特率是否一致、固件是否回应 V1 OPEN。打不开端口时，检查 COM 是否被其他程序占用。
3. 要测阻力，先 **断开**，再选择 **模拟 VR 比赛**、人物和策略，重新 **连接**。面板会向本机 `127.0.0.1:19102` 每约 200 ms 发心跳。端口占用时可另选调试端口。换策略要断开重连并重新握手，设备可能需要本地重新授权。人物资料和参数为虚构演示值，`demo` 始终使用原控制。
4. 顶部提示“准备就绪”后点 **开始**。在机械角度进入阻力生效区时，右栏会出现非零目标。**暂停** 后正常目标归零但角度仍可变化。**继续** 需重新满足遥测和设备许可。**结束** 后可点 **再来一局**，清除等效疲劳并回到准备状态。机械模型不会自动回零。比赛由操作员手动结束。
5. 窗口失去焦点、遥测过期或设备状态异常时，比赛会暂停。重新握手或故障解除后，需要手动继续。PC 后端退出时，重新连接从准备状态开始。

## 看懂右栏的四种数值

| 读取位置 | 含义 |
| --- | --- |
| PC 计算目标 | 控制器请求的阻力幅值，单位 N·m |
| PC 最近完整写出 | 已写完的 V1.1 指令、线序号和有效期，单位 mN·m |
| STM32 已接收序号 | 遥测中由 `ACK_VALID` 标记有效的最近指令序号 |
| STM32 回报目标 | 遥测中的下位机目标，换算为 N·m。要比较命令和回报，先对齐序号 |

`0.000` 是有效零值，`—` 表示当前没有有效读数。测力显示“未提供”时，检查 `FORCE_VALID`。STM32 回报的目标与实际力矩测量是不同字段。一次回报差值也可能来自采样时序或下位机本地限幅。面板显示 V1.1 原始状态位、传输和采样的新鲜度、ACK 进度及 CRC、帧头、序号和组帧超时计数。

点击 **保存本轮日志…**，选择 ZIP 保存位置。压缩包有 PC 原始诊断 `pc.jsonl` 和面板配置、操作事件 `gui.jsonl`。断开后还能保存最近一次连接的记录。勾选 **记录逐帧实验日志** 后连接，ZIP 另含 `experiment.jsonl`。记录 PC 单调时间、MCU 采样时间、会话、实际写出的命令和逐条解析的遥测；文件由后台写入，面板会显示是否丢记录。发给同学时附上复现步骤、固件版本和所用 COM 号。
