## 2. A 组：回推与松手滑行补测（先不改变控制）

V0.5-B CSV 中，narrow+relief 从 q=0.25 rad、静止、2 s 预处理开始，以 +0.065 N·m 回推 2 s。松手瞬间 q=0.01633876 rad，机械速度 omega=+0.46692223 rad/s（qdot 为负），此后目标幅值为 0，1 s 后 q=-0.314528537 rad、omega=+0.224594829 rad/s。

模拟器模型为 J=0.05469492132716054 kg·m²，黏性阻尼 b=0.04 N·m·s/rad，原限位与积分不变。无用户输入、无制动且未触限时，omega(t)=omega0*exp(-b*t/J)，q(t)=q0-omega0*(J/b)*(1-exp(-b*t/J))。按上述松手初态预计 1 s 滑行约 0.331 rad，与 CSV 一致。注意这个解析式适用于当前理想化自由滑行，不能用来预测实物。离散积分略有差异。

### A1. 同起点大角度回推

- person_02 + balanced；legacy/symmetric、narrow/symmetric、narrow/relief 作为固定候选。q=0.25、0.40 rad，初始速度 0，沿用 2 s 固定静止预处理；两种 narrow 的初始目标、疲劳逐步相等。
- 使用 0.065、0.12、0.18 N·m 三个预设软件回推幅值，持续 2 s 后松手 2 s。原 0.065 的首 1 s 与 V0.5-B 比较复现；不因某组触限而删除结果。可按需要补一组 0.10 rad 低角度，但不扫大量参数。
- 记录回推阶段到 q=0.05/0 的时间（区分有施力和松手后到达）、松手时 q/omega、过零速度、松手后 1 s 与 2 s 位移、峰值速度、到达对手侧判定角线及连续保持时间、模拟限位和耗能。达到角线不等于正式比赛获胜；触限后的位移/速度不代表自由滑行。
- q=0.40 的高目标请求与速度相关系数可能使很小的回推速度仍承受较大阻力；用固定速度探针解释，不简单宣称减阻失效。

### A2. 相同释放初态的独立滑行诊断

- 在测试 harness 设置完全相同的 q/omega，而不是正常比赛中瞬移。选取 q=0.05、0.02、0 rad 和机械回推速度 +0.1、+0.3、+0.47 rad/s（可以少量删减重复工况），模拟用户力矩始终为 0，比较 narrow/symmetric 与 narrow/relief；至少核实一个固定释放初态的解析/离散结果。
- 重点验证两种 narrow 在自由区内均不提供额外制动，若后续状态仍在自由区且未触限，其滑行轨迹应相同。不同自然回推试验的滑行差异主要来自释放时初始速度/位置不同。
- 另选一条从阻力区内释放的同初态试验，区分仍有制动和进入自由区后的滑行。记录初始化/预处理、初始制动目标、速度及疲劳，不能让控制状态差异混入比较。
- 不把软件的 release 按键作为 PC 控制器的真实传感输入。当前只有机械角度与速度，不能据此确认人已松手。**本轮先量化问题，不新增近零位速度制动、强制回零、锁止、主动驱动或更复杂的退让控制。** 若认为需要这些措施，作为后续台架研究建议，说明对正常回推的代价。真实磁粉制动器零电流残余阻力、静态抗转矩、实际惯量/阻尼都未标定。

## 3. B 组：最小反应延迟（与 A 组隔离）

V0.2 的一阶建立常数描述“开始发力后需要多久接近目标”，不是“察觉变化后等多久才开始发力”。本阶段仅做一次可开关的**初次阻力需求响应延迟**，不声称模拟任意人体神经反应或识别突然发力。

- 优先 narrow + symmetric + balanced + person_02，排除方向减阻与节奏相位等影响。保留原有静态曲线、策略比例、0.40 s 建立常数、疲劳参数和机械模型。A 组不启用延迟。
- 可选软件 TCP 参数 `--reaction-delay-ms`（默认 0），首轮仅比较 0、100、200 ms。限定有限非负演示范围并校验。无需新增人物元数据或为三个人物分别拟合延迟。demo 在任意设置下旁路；real.run 不接受新选项。
- 建议触发条件为有效 running 内首次出现正的策略/方向调制后阻力请求（即 narrow 越过自由边界产生正请求），而不是单纯进入 running。长时间停在自由区不会预先消耗等待时间。延迟期间目标输出保持 0；等待结束且仍有需求，才从当前请求开始原缓升，不重放旧力矩，不补积分等待时段。
- 延迟只作用于一次新的需求建立，不让所有输入变化都经过历史队列。需求重新归零时撤销并重新准备，暂停、结束、waiting、角色确认切换、断联、过期、故障及异常长时间间隔时撤销等待与原发力建立状态；恢复有效运行后按当前需求重新触发。短暂暂停/故障/过期后立即刷新也不能沿用之前的等待。需求下降、自由区归零以及所有 STOP/0 不得延迟。边界抖动若出现反复触发，先记录，只有确实影响结果时才考虑简单阈值/防抖；默认不增加复杂状态机。
- 延迟用 monotonic now 与实际有效间隔，重复时刻、时间回退及超过既有连续控制间隔时不得增加或追补等待。门开启时不要将整个等待区间计入 V0.2 缓升。
- 疲劳负载代理使用延迟门后的有效请求，门关闭时为零（仍可按原恢复规则更新）；0 ms 时走原计算，逐步精确保持 V0.5-B。明确这是软件负载假设，而非实测肌肉活动。
- 日志仅在 PC 增加必要的原请求、等待状态/时间及门后有效请求等诊断，原有状态字段和两套通信报文不扩展。始终满足下发非负、不超门后疲劳目标/人物上限，制动力矩反向，模拟功率非正。

### B 组验证

1. 固定遥测：先在自由区等待足够长时间，再以固定正目标角度（例如 q=0.25/0.40 rad）和固定推进速度输入；比较三档从触发到门开启/首个正输出的时刻、之后缓升曲线、峰值与疲劳。说明 20 ms 步长的量化误差。比较需求撤销、等待期间松手代理（角度回到自由区）、暂停/故障、重新触发等情形。零速下非零目标不代表主动机械出力。
2. 相同用户施力闭环：沿用原序列与 0.065、0.09、0.12 N·m 的预设幅值，比较峰值推进、首跨阈值/保持、触限、阻力建立过程、疲劳。可复用 V0.5-B 对照脚本。不为选出有利延迟而改变其他参数，不预设较慢或较快一定更好。
3. 保留原全部控制回归；新增必要的门状态/时钟/故障测试。正式 VR 主场景只做代表性实际联网复验，如已完成关键状态的自动回归，不要求所有候选重复整套 35 项检查；若 Unity 不可用，先交付独立软件结果，注明未执行。
