# STM32F405RGT6 ↔ PC 串口协议 V1（供下位机组确认）

> 状态：**建议冻结的应用层接口草案**，不是已经在 STM32 实机上通过测试的协议。组内确认后再以 V1 作为双方唯一依据。上位机的 `common/serial_protocol.py` 提供 Python 编码、解析参考实现；该文件仅依赖标准库，不会打开 COM 口或改变现有控制循环。真实串口接入随后放在 `real/`。

## 1. 为什么采用这套协议

- 系统只有 1 个 STM32、1 个 Windows PC，主要传输角度、角速度、可选的实际测力、设备故障与目标**制动阻力幅值**。不需要消息总线或大规模通用协议。
- 使用 **二进制定长字段 + 帧头 + 长度 + 序号 + CRC16**；这是一条字节流，既可以通过 **USART + 3.3 V USB 转串口**，也可以通过 **STM32 USB CDC 虚拟串口**传输，应用层帧内容完全一致。
- 同一套公共控制函数继续计算目标阻力；**通信帧不携带 PWM、励磁电流或任意方向的驱动力矩**。STM32 负责本地限幅、PWM/电流映射与保护。
- 借鉴 [TinyFrame](https://github.com/MightyPork/TinyFrame) 的长度、序号和校验思路；没有复制其代码或引入其运行时。也考虑过 [COBS-C](https://github.com/cmcqueen/cobs-c) 的分帧方式，但本项目采用更容易在 STM32 HAL 中直接实现的简化帧头协议。

## 2. 统一传输规则

- 每个字段都按 **小端序 (little-endian)** 逐字节编码；不能直接 `memcpy` 带有 C 结构体填充的内存。
- `int32` 为有符号二进制补码，`uint16` 为无符号整数；不发送浮点或字符串。
- 角度：**mrad**（千分之一 rad）；角速度：**mrad/s**；力矩：**mN·m**（千分之一 N·m）。例如 `-0.400 rad` 发送 `-400`，`0.600 N·m` 发送 `600`。
- 下位机上传的数据必须是**机械摆臂主轴侧**的角度和角速度，经零位、传动比、编码器方向换算完成。与上位机现有约定保持一致：`θ=0` 为起始零位，用户向获胜方向压下时 **`θ` 变负，`q=-θ` 变正**。实际装配仍需要标定符号。
- 物理接口初步建议 `115200 / 8N1`（USART + 转接板时）；USB CDC 可使用同样的应用层帧，但 COM 口设置的波特率不代表 USB 总线实际速率。
- 约定单条 payload 最大 **32 字节**；上位机按字节流接收，不能认为一次串口 `read()` 就是一帧。

### 2.1 帧结构

| 字节偏移 | 字段 | 长度 | 定义 |
|---|---|---:|---|
| 0–1 | `SYNC` | 2 | 固定 `A5 5A` |
| 2 | `version` | 1 | `01` |
| 3 | `type` | 1 | `01` 遥测；`02` 制动命令 |
| 4–5 | `seq` | 2 | `uint16 LE`，发送方独立递增，65535 后回到 0 |
| 6 | `length` | 1 | `0..32`，只表示 payload 字节数 |
| 7.. | `payload` | N | 依据消息类型解释 |
| 7+N..8+N | `crc16` | 2 | `uint16 LE`，对 **version 到 payload** 所有字节计算，不包含 `SYNC` 和 CRC 本身 |

总帧长 `9 + N` 字节。CRC 算法是 **CRC-16/CCITT-FALSE**：`poly=0x1021`、`init=0xFFFF`、无反射、`xorout=0`，`"123456789"` 的校验值必须是 `0x29B1`。不要与 Modbus CRC16 混用。

`seq` 在同一发送会话内递增。接收方保存上次成功接受的序号，只有 `0 < ((seq - last) & 0xFFFF) < 32768` 才认定是更新；重复和旧序号不执行，也**不延长命令有效期**。串口重开或设备复位后，由双方重新建立序号基准；正式固件需避免故障后的自动重新使能。

### 2.2 STM32 → PC：遥测 `type=0x01`

Payload 固定 **18 字节**（原始字节偏移以 payload 开始为 0）：

| Payload 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0–3 | `angle_mrad` | `int32 LE` | 当前主轴角度，单位 mrad |
| 4–7 | `velocity_mrad_s` | `int32 LE` | 当前主轴角速度，单位 mrad/s |
| 8–11 | `sensor_force_mn` | `int32 LE` | **测力传感器的力**，单位 mN；未接入时填 0 且 FORCE_VALID=0 |
| 12–13 | `status_flags` | `uint16 LE` | 状态位，见下 |
| 14–15 | `last_command_seq` | `uint16 LE` | 最近**成功接受**的命令序号，仅在 `ACK_VALID` 置位时有效 |
| 16–17 | `applied_target_mnm` | `uint16 LE` | STM32 限幅后当前执行的**目标阻力幅值**（mN·m）；**不是传感器实测力矩** |

状态位：`bit0 READY`、`bit1 FAULT`、`bit2 ESTOP`、`bit3 LIMIT`、`bit4 ACK_VALID`、`bit5 FORCE_VALID`；其余保留为 0。只有 READY=1 且 FAULT/ESTOP/LIMIT=0 才可进入正常输出。ACK_VALID=0 时 `last_command_seq` 忽略。

**注意：** `sensor_force_mn` 是力传感器的实测力，不是已经换算到主轴的力矩；实际安装方向、拉/压正负号及单位换算仍需标定。`FORCE_VALID=0` 时 PC 必须忽略该字段，不得把 0 当作实测零力。这里的 `applied_target_mnm` 表示本地下发给执行映射的目标值，不是经过传动机构测得的实际力矩；未来如果增加力传感器，必须使用另外的字段或消息类型单独表达。

### 2.3 PC → STM32：制动命令 `type=0x02`

Payload 固定 **5 字节**：

| Payload 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `mode` | `uint8` | `0=STOP`，`1=ENABLE`；其他值拒绝 |
| 1–2 | `target_torque_mnm` | `uint16 LE` | **无符号目标阻力幅值**，单位 mN·m |
| 3–4 | `valid_for_ms` | `uint16 LE` | 自**最后一条有效命令实际收到时**起的有效期；建议 200 ms，协议允许 20..500 ms |

`STOP` 必须携带 `target_torque_mnm=0`；STM32 遇到故障、急停或越限应有本地优先级更高的保护，不得被 ENABLE 覆盖。`0..65535 mN·m` 只是帧字段的编码范围，**绝不是允许对人体施加的力矩范围**。设备应按机械、制动器和台架标定得到的安全限值截断。

此处只发送阻力**大小**，不发送需要电机主动推动用户的正/负驱动力矩。真实磁粉制动器的励磁电流→抗转矩映射由 STM32 与电气组标定。上位机 `common/control.py` 当前的有符号力矩仅用于仿真和状态查看，不直接下发到真实执行器。

## 3. 时间、错误和保护约定

- 初始演示频率：STM32 遥测 **100 Hz**；PC 指令 **50 Hz**。在当前 18 B 遥测和 5 B 命令负载下，整帧分别为 27 B 与 14 B，115200 波特率具有充足带宽余量。
- 上位机遥测超过 **250 ms**、VR 心跳超过 **1000 ms**（沿用现有桥接默认值）或设备上报故障时，停止正常控制计算并发送 STOP。下位机不依赖上位机完成断连检查：若 **200 ms** 内没有收到新的有效命令，执行已确认的本地故障/停机处理。
- CRC 错误、长度超限、未知版本/类型、错误 payload 长度、重复或乱序命令均拒绝，不更新看门狗；遇到坏帧从下一处 `A5 5A` 尝试重新同步。不能因单次损坏而持续使用旧命令。
- STM32 接收缓冲建议由 UART 中断/DMA 或 USB CDC 回调接收字节，帧解析在后台任务完成，**不要在接收中断内进行阻塞 UART/USB 发送或复杂控制计算**。
- 急停应保持硬件独立保护，复位必须经状态确认和人为重新使能。`STOP` 在这里仅表示目标阻力为零，**不等于真实机械安全停止**；尤其要验证断电、突然卸力、机构自重和机械止挡的行为。
- **关键控制方式：** 上位机 PC 不需要等待遥测与 VR 每个周期同时到达；采用最近的有效数据计算，但过期后立即停止正常输出。未来可以扩展独立事件确认消息，V1 不把简单持续心跳伪装成“可靠事件事务”。

## 4. 双方核对用的十六进制样例

第一条：STM32 遥测，`seq=34`、`angle=-0.4 rad`、`velocity=-0.2 rad/s`、`sensor_force=12.5 N`、`READY|ACK_VALID|FORCE_VALID`、最近命令 `seq=33`、当前目标 `0.3 N·m`：

```text
A5 5A 01 01 22 00 12 70 FE FF FF 38 FF FF FF D4 30 00 00 31 00 21 00 2C 01 F0 3F
```

第二条：PC 指令，`seq=42`、`ENABLE`、`0.6 N·m`、有效期 `200 ms`：

```text
A5 5A 01 02 2A 00 05 01 58 02 C8 00 3A 4A
```

第三条：PC 指令，`seq=43`、`STOP`、目标为零、有效期 `200 ms`：

```text
A5 5A 01 02 2B 00 05 00 00 00 C8 00 20 39
```

可以让下位机同学使用任意 C 语言实现编码、CRC、解析，并核验上述三个样例的**每一个字节完全一致**。如果不一致，先处理端序和 CRC 设置，再接实际执行器。

## 5. 上位机参考和使用边界

- `common/serial_protocol.py`：`telemetry_frame()`、`command_frame()`、`FrameParser.feed()`、`decode_payload()`；只用 Python 标准库。
- `common/test_serial_protocol.py`：编码解码、CRC、分包/粘包、错误帧恢复、序号回绕等测试。
- 当前 `common/bridge.py` 依然保持 **模拟 STM32 的 TCP 9101** 与 **VR 的 UDP 9102**；**尚未将真实 COM 口接入主桥接循环**。真实串口适配器之后在 `real/` 开发，需用 `pyserial`，Windows 可用 `COMx`，Linux 可用 `/dev/ttyUSB*` 或 `/dev/ttyACM*`。
- 此协议不要求 STM32 一定选择 USART + 转接器还是原生 USB CDC。两者均可使用同一应用层帧；下位机主要修改底层驱动。
